# 人设卡规范

这张卡是引擎的第一输入。Ren'Py 版每批请求都把它整段塞进 system prompt，对话模式每回合先读它。卡写不好，后面所有生成都在猜。

文件位置：

- `game/persona/<id>.md`，一张卡一个角色，文件名用英文 id，和 frontmatter 的 `id` 一致

一个角色一个文件。frontmatter 决定绑定关系，正文决定她会说什么。世界观不写在人物卡里，单独放 `game/seikai.md`，见 `references/seikai.md`。

## frontmatter

```yaml
---
id: aya
name: 绫
illustration: aya
aliases: [小绫, 阿绫]
lead: true
---
```

| 字段 | 作用 | 注意 |
|---|---|---|
| `id` | 人物卡的键 | 留空时用文件名 |
| `name` | 台词里的说话人，也是模型该写的 speaker 值 | 正文里出现别的叫法会被当成另一个人 |
| `gender` | 性别，只写 `female` / `male` / `other` | 进生图提示；不写时可能画出和设定不符的性别。不要写中文 |
| `illustration` | 兼容字段，留空即可；写了就额外去 `picture/standing/<illustration>/` 找立绘 | 老版本素材迁移时用 |
| `aliases` | 别名，命中也算这个角色，大小写不敏感 | 用英文逗号分隔，不要加引号；用来兜住「她」「学姐」这类称呼 |
| `lead` | `true` 标记女主角 | 多张卡时靠它选，没写就按文件名排序取第一张；`GALGAME_HEROINE` 优先级最高 |
| `romance` | 是否可攻略，默认跟随 `lead` | true 才结算好感、才写恋爱线；false 只按身份和关系写，不写心动和暧昧 |
| `affection` | 初始好感度 0–100，默认 0 | 只对新档开局生效；之后以存档里的当前值为准，引擎注入时会分别说明"初始"和"当前" |
| `voice_name` | 阿里云百炼文生声的固定音色名，如 `Cherry` | 不写就用 options 里的 `GALGAME_VOICE_NAME`；OpenAI 兼容接口不需要这个字段 |

文件名以下划线开头的（`_TEMPLATE.md`）不会被当成人物卡。

## 正文要写的四节

顺序照抄，缺哪节模型就在那处自由发挥。

1. **开头一段**。她是谁、几岁、性别、和「我」是什么关系。这一段会直接注入模型。
2. **角色详细介绍**。**整段直接喂给模型**，不用按固定条目：性格、背景、说话方式、雷区、加分、关系变化都写在这一节，可以分段也可以列点。越具体越好，模型会照这个演，不会自己加设定。
3. **外貌与身体语言**。生图要用：发型、服装、身高、惯用姿势写死；不写死，每次画出来都不是同一个人。不打算生图时可以只写动作习惯。
4. **立绘**。每个差分五行键值：`id`、`衣服`、`动作`、`表情`、`什么时候用`。图片放 `picture/standing/<id>/<立绘id>.webp`，`id` 必须是数字，`衣服` 写这套衣服。

frontmatter 的 `gender` 只写 `female`、`male` 或 `other`，会进生图提示。老卡里的中文会在加载时自动换成英文，新卡直接写英文。

立绘这样写：

```markdown
## 声音

开语音时用得到，写她的音色、语速、口音和说话习惯，比如「年轻女声，声音偏轻，语速慢，句尾会弱下去」。声生声时这段只作补充，主要靠 `voice_example/<角色名字>.wav` 的参考音色。OpenAI 兼容接口会把它当 `instructions`；阿里云百炼不认自由描述，要在 frontmatter 用 `voice_name` 选固定音色。

## 立绘

### 立绘 1

id：1
衣服：藏青校服外套，袖口卷两折
动作：站着，双手在身前交叠
表情：眼睑下垂，嘴角平直
什么时候用：默认；防备、被问到不想答的事

### 立绘 2

id：2
衣服：藏青校服外套，袖口卷两折
动作：微微侧身，右手抬到胸前
表情：视线抬起，嘴唇微张
什么时候用：愿意多说一句；被记住细节时
```

`### 标题` 只是给人看的，引擎只认五行键值。冒号中文英文都行，顺序不限，但每个差分必须写 `id`，而且必须是数字；`衣服` 必须和「外貌与身体语言」里的同一套对得上，**同一件事里不能换衣服**。换装只能在正文里明确交代（隔天、加了外套、换了校服）。

差分 id 以人物卡「## 立绘」为准，写几节就能用几节。人物卡的 id 和文件夹里的文件对不上时，那一拍的立绘会缺，引擎用透明占位顶上。

引擎会自己加一节 `## 剧情设定`，每 `GALGAME_DETAIL_INTERVAL`（默认 50）拍把新剧情里的长期设定合并写回，上限 `GALGAME_PERSONA_MAX` 条。这节可以手工编辑，但不要指望它替代上面四节。

## 阶段与解锁

阶段名和阈值在引擎里是写死的五档：陌生 0–19 / 熟悉 20–39 / 心动 40–59 / 暧昧 60–79 / 恋人 80+。卡里要按这五档分别写清"这一档她会做什么"和"这一档她绝不做什么"。

人设和剧情冲突时，人设赢。剧情这回合需要她热情，但她这一档不会热情，那就让剧情慢一回合，不要让她 OOC。

## 写完自检

- 把卡里任意一句台词换成另一个角色的名字，还成立吗？成立就说明写得太空。
- 外貌节能不能直接拿去生图？不能就说明缺发型、服装、体型。
- 雷区能不能被玩家踩到？写了一堆雷区却没有对应的选项能触发，等于没写。
- 立绘每节的 `id` 和 `picture/standing/<角色id>/` 里的文件名对得上吗？每个 `什么时候用` 是不是都能落到具体剧情？

空白模板见 `assets/renpy/game/persona/_TEMPLATE.md`。
