# 美术资源规范

背景图和角色立绘的命名、尺寸、提示词与后处理。`scripts/gen_art.py` 按这份规范实现，手工出图也照这里的规格交付。

## 目录

所有图片统一放在 `game/picture/` 下：

```
game/picture/
├── scene/<time>_<place>.jpg                    背景，文件名就是场景 id
├── standing/<id>/<立绘id>.webp           立绘，目录是角色 id，文件名是立绘 id
└── ui/choice.png / dialogue.png / title.png    界面装饰，可选
```

`<id>` 取人物卡 frontmatter 的 `id`，和 `persona/<id>.md` 的文件名一致。

两个固定目录：

- `picture/standing/all/<数字>.webp` — 「全员」同时说话时用的群像
- `picture/standing/me/<数字>.webp` — 玩家角色立绘，只有 `GALGAME_PLAYER_SPRITE=1` 时才显示
引擎会依次找 `picture/standing/<id>/`、`picture/standing/<illustration>/`，最后才是中文角色名目录，所以老素材不用改也能读。

界面装饰三张：

| 文件 | 用在哪 | 建议 |
|---|---|---|
| `ui/choice.png` | 选项按钮底纹 | 横条，深色半透明，四角留 18px 可拉伸区 |
| `ui/dialogue.png` | 对话栏 | 横条，深色半透明，四角留 24px 可拉伸区 |
| `ui/title.png` | 首页背景 | 1280×720 或更大，会按 cover 铺满 |

三张都是可选的，没有就用引擎默认样式。文件名固定，不要改。

## 背景

文件名 `时间_地点.jpg`，时间只有三种：`day` 白天、`dusk` 黄昏、`night` 夜晚。引擎扫 `picture/scene/`，只认这三个前缀，其它前缀的图不参与场景。

一个地点要覆盖它会出现的时间，缺哪张，写到那个时段时就只能沿用别的图。目录里一张都没有时，引擎用内置的 11 组校园组合兜底，但同样需要你自己补图。

中文时间词可以改，写在 `game/time_words.json`：

```json
{"day":["清早","上午"],"dusk":["闭馆前","傍晚"],"night":["打烊后","深夜"]}
```

规格：**1280×720**，JPG，quality 85。这是 Ren'Py 默认分辨率，出图尺寸和它一致就不缩放，字不会糊。

画面里不能有人，不能有任何可辨认的文字。同一个地点要覆盖它可能出现的时间，缺一张，模型写到"夜晚教室"时只能沿用黄昏图，时间就对不上。

提示词骨架（gen_art.py 内置，`art_prompts.json` 可逐张覆盖）：

```
日系恋爱视觉小说（<题材>）的游戏背景插画。<地点描述>，空镜头，画面里没有任何人。
时段：<time>，<该时段的光线>。手绘赛璐璐上色，柔和景深，构图留出角色站位和文字框区域，
细节丰富但不抢视线，色彩统一。画面里不得出现任何可辨认的文字、字母、数字或标志，
书脊和招牌一律做成模糊色块，不要人物不要水印。
```

实测两点：

- 万相 2.1 每边限制 512–1440，横图给 1280\*720 正好。
- 书脊和招牌是重灾区，第一次跑出来左下角一整条乱码。把"书脊和招牌一律做成模糊色块"写进正向、把 汉字/字母/数字/招牌文字 加进负向之后才干净。仍然冒字就 `--force --seed` 换个数字重抽那一张。

## 立绘

路径 `picture/standing/<id>/<立绘id>.webp`。

`<立绘id>` 是人物卡「## 立绘」里每个键值块的 `id`，一个数字，文件名就是它。块里的动作、表情、什么时候用会一起进提示词。文件名不带角色名，角色由所在文件夹决定。

规格：**920×1380**（2:3），WebP，quality 88，**全身**，透明背景。全身是因为引擎按 `shot` 缩放贴图，半身图放远了就变成一张脸飘在屏幕上。PNG 一张 1.2MB 转 WebP 后约 115KB，首次显示不卡。

出图尺寸建议 960\*1440，抠图后等比放进 920×1380 画布，底边对齐、水平居中，这样脚的位置在每个表情里都一样。

提示词骨架：

```
日系恋爱视觉小说角色立绘，全身，站姿，正面微侧，脚尖朝前。
固定设定：<外貌>。服装、发型、体型、配色必须和其它表情的立绘完全一致。
这一张的表情与姿态：<该表情的说明>。
背景是均匀的纯白，无渐变、无纹理、无投影、无地面、无道具，
人物完整不裁切，居中竖构图，赛璐璐厚涂边缘干净，画面里不要任何文字。
```

`<外貌>` 直接取人物卡「外貌与身体语言」那一节。这就是为什么规范里要求那一节写死发型、服装、身高：实测只写"二十岁，图书馆管理员"，模型给了一个短发男生，和卡里想表达的人完全不是同一个。

`<该表情的说明>` 取人物卡「立绘」一节的冒号后面那句，比如 `- calm：平静，默认` 就填"平静，默认"。

表情之间要像同一个人，做法有两层：

1. 每条 prompt 都重复同一句固定设定，并明写"必须和其它表情一致"
2. 还散的时候改用图生图，把已有一张当参考，只改表情关键词

## 用户自己提供的立绘

很多时候立绘是别人画好、或者你已经抠好的，不要硬塞给生图模型。用 `scripts/import_standing.py` 转成框架规格，它和 `gen_art.py` 走同一套归一化，所以自提供图和生成图在游戏里一样大：

```
# 单张：透明 PNG、白底 JPG 都行
python scripts/import_standing.py --game-dir . --role aya --id 1 --file ./她的立绘.png

# 批量：文件名就是立绘 id，1.png / 2.webp / aya-3.png 都认
python scripts/import_standing.py --game-dir . --role aya --dir ./立绘/

# 白底图颜色偏灰，放宽容差；已经透明的图强制不抠
... --tol 40
... --cutout off
```

**立绘开关为 0 时，这一步不抠图**：`GALGAME_GEN_STANDING=0` 表示只用现成图，`gen_art.py` 不再排立绘任务，`import_standing.py` 也原样保留你给的图（白底就还是白底），只做尺寸归一化。要抠图就把它设成 1 或 2，或者显式加 `--cutout on`。

它做的事：

- **有透明通道的图直接跳过抠图**，不碰边缘，避免把已经干净的头发丝二次处理
- 没有透明通道的按白底抠图（和 `gen_art.py` 同一套四边洪水填充 + 1.2px 羽化）
- **按内容包围盒归一化**：把人物缩放到画布高度的 96%，底边对齐、水平居中。不是按整张图缩放，所以每张留白不同也不会一张头大一张头小
- 统一输出 `920×1380` 透明 WebP（或 `--format png`），路径 `picture/standing/<角色id>/<立绘id>.webp`
- 源图备份到 `picture/_import_src/`，并在 `art_manifest.json` 记 `"model": "imported"`
- 目标已存在时跳过，加 `--force` 才覆盖；`--dry-run` 只打印路径

对源图的建议：全身、脚在画面底部、四周留一点空白，别裁到头发和鞋；同一角色的几张图最好同一批画，姿势差异别太大。尺寸不一致、带不带透明都没关系，工具会统一。

如果接受 `cover` 的裁切（半身图想铺满画面），加 `--fit cover`；默认 `contain` 保留完整人物。

## 抠图

白底抠图用四边洪水填充，不要整图按颜色阈值删，那样会把白衬衫、白皮肤一起抠穿。

- 从四个角和四条边的中点共十个种子做 floodfill，只清除与边界连通的近白区
- 按背景色距离生成 alpha 后，边缘做 1.2px 高斯羽化，硬边会看出一个白框
- 抠完按 alpha 的包围盒裁掉透明边，再等比放进目标画布

实测：合成图 34% 覆盖、四角 alpha 为 0；真实出图的人物边缘干净，没有白边残留。

## 跑一遍

```
python scripts/gen_art.py --game-dir . --dry-run     # 先看提示词
python scripts/gen_art.py --game-dir .               # 全量生成
python scripts/gen_art.py --game-dir . --only scenes # 只补背景
python scripts/gen_art.py --game-dir . --only aya/1 --force --seed 7
```

立绘差分直接从人物卡「## 立绘」的键值块里读，写几节就出几张，提示词里会带上每一节的动作、表情和使用场合。

密钥读 `GALGAME_IMAGE_KEY`，留空就复用 `GALGAME_KEY`。原生异步接口和 OpenAI 兼容接口都支持，靠地址里有没有 `compatible-mode` 判断。产物清单写在 `game/art_manifest.json`，每张图的提示词和模型都在里面，方便复现。

想逐张改写描述，就在 `game/art_prompts.json` 里覆盖：

```json
{
  "scenes": { "dusk_station": "雨后的月台，自动贩卖机的灯映在湿地面上" },
  "characters": {
    "aya": {
      "look": "齐肩黑发，左耳一颗小银钉，米色针织衫配深灰长裙",
      "style": "日系恋爱视觉小说角色立绘，全身，站姿，双手插在裙侧口袋里",
      "moods": { "calm": "眼神平视，嘴角没有弧度", "bright": "眼睛弯起来，笑得很浅" }
    }
  }
}
```

空白样例见 `assets/renpy/game/art_prompts.example.json`。

## 检查

- 背景文件名在 `picture/scene/` 里，时间只用 day / dusk / night，尺寸 1280×720
- 每个地点覆盖了它会出现的所有时间
- 每张背景四个角落看一遍，有没有乱码文字
- 立绘是否透明、边缘有没有白边、脚有没有落地
- 同一角色的几张脸是不是同一个人，发型服装有没有飘
- 人物卡「立绘」的 id 和文件名一致
- 体积参考：背景 11 张约 2MB，立绘 3 张约 350KB
